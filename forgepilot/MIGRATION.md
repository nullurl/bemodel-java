# 工业迁移与数据契约

## 技术复用与行业重建

| 上游模块 | 工业处理 |
|---|---|
| ontology / modeling | 保留CRUD、人工审核、不可变发布和本体自检；导入工业DRAFT对象与关系 |
| datasource / mapping | 保留注册、连接加密、物理扫描和人工映射；提示词改为工业上下文 |
| glossary / knowledge | 保留术语、指标及文档审核；不导入医院知识种子；工业指标未配置探针时不出数 |
| seed / db/migration | 原医疗配置留存；工业配置采用独立基线与工业种子 |
| clinical / flow / medical RDF | 工业配置拒绝这些API；不将临床规则包装为工业质量规则 |
| cs / lab / simulation / reconciliation | 依赖医疗示例SQL和剧本，工业配置暂不开放；待按实际工业数据和授权重新验收 |
| ForgePilot runtime | 原业务事务、权限与守卫继续管理实例；Java平台管理语义定义，不接管原业务事实 |

`V1__industrial_platform.sql`从上游45个迁移中仅提取平台表的59条CREATE/ALTER语句，保留顺序及来源哈希；不执行任何医疗CREATE DATABASE、医疗业务表、INSERT、UPDATE或DELETE。`V2__industrial_ontology.sql`插入工业对象、属性、关系、规则、指标、术语与本机演示账号。整个模型以DRAFT保存，完整契约另存`fp_model_contract`，保留单位、类型、来源和基数等上游表无法完整表达的信息。

本期没有把SQLite JSON集合或HTTP路径冒充MySQL物理表写入`bm_mapping`，没有注册任何虚假可连接的ERP源。`bm_datasource`和`bm_mapping`应为空；未来取得真实源字典、只读凭据、组织授权后，才按实际表列映射。禁止对已有医疗数据库执行工业基线，也不使用Flyway baseline-on-migrate掩盖混库。

## 身份与数据匹配

- 企业目标身份为`tenant + source_system + source_record_id`；当前演示单案例用`run_id + entity_type + business_id`隔离，每条快照注明`simulation=true`。
- `EvidenceVersion`用`evidence_id + version`，防止不同证书的v1合并；历史更正版本保留。
- 只有明确的源外键/引用列表才生成实例关系，不按同名、相同金额或文本相似度自动合并，不沿关系做传递推断。
- 示例中的`Demand.material=PP-R01`、`plant=A-01`、外部订单行号保留为源编码，物料、场地、客户订单主对象仍待建立权威映射；不能从一个字符串推断主数据已完整接入。
- 更正证书指向历史批次B0P，而当前库存没有B0P时，记录`target_not_in_snapshot`，不自动重挂到B0，不将历史缺口当作当前物料已合格。
- 供应商回复、报价的实例遵循当前工作台可见范围，不提前暴露种子中的未来记录；全局快照不向供方账号开放。

## 数量、金额、时间与状态

- 现有业务数量为整数kg，金额为整数人民币分。企业目标财务对象采用整数最小货币单位加币种；跨币种无明确汇率与时点不相加。
- 实物库存、供方承诺、条件供给、受限库存、其他订单冻结量与当前需求合格可用量分开；本体页引用原`summary`，不自行重算可用资格。
- 证据有效期可能是日期或带时区时点，保留源精度；日期按案例时区解释。交易证书头有效期在现有源为空时按该演示契约标记`not_applicable`，不造日期；其他缺失时间标为`unknown`。
- 未知、缺失、受限、不适用、源不可用、冲突、过期分别保留；缺失数值为null，不能填0。无当前记录不证明现实中没有业务对象。
- 库存物流状态、性能检验、来源核验、授权放行是独立状态轴。承诺已签署、采购已结清和付款已发生各自记录，不可互相推断。

## 动作与发布

动作契约包含角色、前提、输入版本、结果、副作用、幂等、未知回执及补偿路径。页面所有`execution_enabled=false`。实际批准与库存写入继续在ForgePilot原接口中进行；Java模型CRUD不等于取得业务写权限。

变更模型时重新生成字典、类型引用检查、反例及源对账证据，再审批新版本。已应用的Flyway迁移不可重写：当前迁移尚未正式发布；后续变更应新增V3及以上迁移，而非重跑生成器覆盖已部署V2。模型演化与实例/业务修订分别留痕。上线前由各环节业务owner确认口径，数据owner确认真实字段与范围，系统owner确认鉴权与当前源守卫。
